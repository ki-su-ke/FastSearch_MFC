# FastSearch_MFC

## このプロジェクトは何か

ポートフォリオが必要になった。  
しかし、これまで書いてきたコードは公開できないものばかり。  

というわけで、まずは、MFCで作った検索アプリを公開することにした。  
せっかく作るなら少し捻ったものをやろうと思い、やったことのないUSN Journalを使った検索アプリをテーマとした。  

USNジャーナルについて調べたり、アプリの全体像を構想しているうちに、一つアイデアが浮かんだ。  
せっかくだから、このMFCアプリを既存の資産と見立てて、UIを後で載せ替えよう。  
でも、本当に昔のMFCアプリを作っちゃうとUIの載せ替えが大変だから、載せ替えやすい設計としておこう。  
まるで、こうすれば過去の資産だって現代的なUIに出来ますよ的な。  

という思い付きで作りました。  

思ったより大変な感じになりましたが、実験的なプロジェクトとして、また大いに公開できるプロジェクトとして楽しみながらやれました。  
まだ載せ替えはしていないのでどうなるか分かりませんが、そういうプロジェクトとしておきます。  

## 想定する既存システム
Windows固有で、そのままでは他に移植できないもの。  
とはいえ、現時点でマルチプラットフォームは考えていません。  
あと、上手くできたら自分でも使おうと思い、USNジャーナルを使った検索アプリとしました。  

## アーキテクチャ
MFCをUIとして使い、DLLをロジック部として分離しています。  
きっとMFCやC++資産を活かしたい場合は一旦こういうようにするよねって思ったのでそういう設計にしました。  
世の中の既存資産はこんなことを想定して作られてはいないのは知っていますが、中間地点的なサンプルとして見てもらえればと思います。  

MFC UI
   │
   │ UI境界
   ▼
Native DLL
   │
   ├─ USN Journal
   ├─ Search
   └─ Result management  

イメージとしては上記のようになります。  

DLL境界部はC言語の関数インターフェースにしており、MFC依存をなくしています。  
そうすることで、UIを載せ替えるとか現代的な技術と組み合わせることが容易になる、、はずです。(まだ予定は未定ですが。)  

## 実装しての感想

とそんなことを思いつつ始めましたが、中々気を使うことが多かったのも事実です。  
DLL境界を跨ぐ際にはデータ型のコンバートが必要になったり、メモリ管理をどちらに委ねるのかなど設計判断の連続でした。
せっかくのC++だしと、ポインタの効率的な使い方などを考えたり、USN構造体の色々あったであろう変遷(バージョンがあるとか・・・)を感じたりもしました。  
概ねできたかと思いきや、USNジャーナルはドライブ変更には読み直しが必要だったようで、しっかり非同期処理を組み込む必要がありました。  
当初はもっと気軽に考えていたのですが・・。

とはいえ、いい感じになってきたと思います。
個人的には C++ 20くらいのモダン C++ の練習にもなりました。  

ただ、密かに感じてはいましたが、USNジャーナルは単なる検索に使うものじゃないですね。  
もう少しハードウェア寄りの制御部分とか、ファイル監視とかそういうの向きかなと思いました。
